- Added `MOQParams.audio_out_keepalive` (default on): the MoQ transport now keeps the bot's audio track continuously live by publishing paced silence whenever the pipeline has no audio scheduled, matching how WebRTC transports present a continuous source. The browser player anchors on the first frame it receives and skips frames scheduled in the past, so a track that only carried speech lost the first moments of each utterance to player warm-up — most visibly the start of the greeting on cold starts. Set it to `False` to publish speech only.
